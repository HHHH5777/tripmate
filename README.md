# 旅搭 TripMate

> 中山大学软件工程学院首届「软工菁英杯」技术创新应用大赛 · 初级组 · 主题词「旅行」

把一句自然语言旅行需求，变成一份**可校验、可解释、可导出**的行程单。

- 在线体验：https://hhhh5777.github.io/tripmate/
- 仓库地址：https://github.com/HHHH5777/tripmate

## 一句话说明

用户说「3 天厦门，两个人，人均 800，想看海和吃小吃」，系统先抽取需求槽位，生成一份基线行程，再用 7 条硬约束逐项校验；不通过就带着违规原因自动重排，直到通过或达到重排上限，最后输出行程、预算、出发前清单与分工，并支持导出日历与长图。

## 核心设计

### 1. 结构化优先

行程不是一段文字，而是结构化数据：每天由「交通 / 景点 / 用餐 / 自由活动」等条目组成，带有起止时间、花费、步行距离、室内标记。只有结构化行程才能被规则校验、局部修改和导出。

### 2. 大模型负责想，规则负责算

可行性判定不交给模型自检，而由确定性规则完成，保证可复现、可解释、可测试。当前线上版本为**纯前端规则版**，不依赖任何后端与大模型密钥。

### 3. POI 白名单

所有景点来自内置白名单（厦门 15 个、长沙 14 个），包含坐标、开放时间、闭馆日、门票、时长、标签。白名单之外的景点会被标记为「待核实」，从源头抑制幻觉。

### 4. 校验—重排闭环

基线行程**故意不做地理聚类**，模拟「把热门景点堆在一起」的典型错误，先暴露问题再修复，让闭环价值可见。

## R1–R7 约束

| 编号 | 约束 | 阈值 |
| --- | --- | --- |
| R1 | 每日有效活动时长 | ≤ 10 小时 |
| R2 | 相邻两点交通耗时 | ≤ 45 分钟 |
| R3 | 单日步行总量 | ≤ 12 km（标准节奏） |
| R4 | 预算 | 不超过人均上限，且预留 8% 机动 |
| R5 | 景点合法性 | 白名单 + 开放时段 + 闭馆日 |
| R6 | 天气 | 有雨天必须给出室内备选 |
| R7 | 首末日 | 景点数量限制 + 返程前 60 分钟缓冲 |

每条违规都包含规则编号、严重级别、自然语言说明、建议动作和定位目标，重排模块据此执行具体动作（换点、删点、调整顺序、替换为同区域景点等）。

## 功能

- 需求槽位抽取：城市、天数、人数、人均预算、节奏、偏好标签
- 行程生成：按天分配景点，自动插入交通、午餐、晚餐、休整
- 校验报告：逐条列出违规与修复动作，展示重排前后对比
- 预算明细：交通、住宿、餐饮、门票、机动
- 出发前清单与三人分工
- 导出：`.ics` 日历文件、SVG 行程长图（可预览、可下载）
- 离线可用：无网络、无密钥也能完整跑通

## 使用方式

### 在线

直接打开 https://hhhh5777.github.io/tripmate/

### 本地

不需要安装任何依赖，双击 `index.html` 即可；或起一个静态服务：

```bash
python -m http.server 8000
# 浏览器访问 http://localhost:8000
```

## 仓库结构

```
.
├── index.html   # 页面结构、样式与交互框架
├── app.js       # 数据（POI 白名单）、槽位解析、行程生成、校验、重排、导出
└── README.md
```

## 技术选型

- 原生 HTML / CSS / JavaScript，零依赖、零构建，单页体积约 75 KB
- 规则引擎以纯函数实现，输入槽位与 POI 库，输出可序列化的行程对象
- 导出不依赖第三方库：`.ics` 手工拼装 iCalendar，长图用 SVG 直接生成
- 部署在 GitHub Pages，推送即自动重建

## 已知边界

- 内置城市为厦门、长沙两座，覆盖 3 天以内的短途行程
- 线上版本为规则版，未接入大模型；景点库与交通估算为离线近似值，不构成实时预订依据
- 夜间开放景点（如夜游项目）当前不参与白天排程
